目录中看到的文件路径只是命名入口；实际数据可能分布在多个不连续的数据区间，也可能存在于文件记录内部、压缩单元、稀疏空洞或加密容器中。要回答“文件的第一个扇区在哪里”，必须先确定是在问**文件第一个逻辑字节**、**第一个已分配数据簇**还是**取证工具报告的第一个物理/设备扇区**。三者在特殊文件中可能不同。

本文讨论如何从文件系统元数据重建文件逻辑偏移到存储位置的映射，并验证取得的字节是否确实属于目标文件。若尚未区分设备 LBA、分区偏移和文件系统起点，请先阅读[存储寻址基础：扇区、LBA、分区与偏移](./storage-addressing-sectors-lba-offsets.md)。

<a id="section-1"></a>
## 1. 文件定位应建立两条关系

一条关系连接文件名与文件对象；另一条关系连接文件逻辑内容与分配空间。

```text
目录项 / 文件名
      ↓ 解析
文件元数据对象（FAT 目录项、exFAT File Set、NTFS MFT、ext inode）
      ↓ 读取数据位置映射
逻辑区间：文件 [0, length)
      ↓ 映射至一个或多个范围
文件系统簇 / 块 / 元数据驻留内容 / 稀疏空洞
      ↓ 按文件系统与卷参数换算
卷相对字节位置 → 分区/设备逻辑字节流
```

文件名、文件对象标识和数据地址不是同义词。一个元数据对象可以有多个名称（硬链接）；一个文件可能有多个数据流；而一个逻辑范围也可能不占用独立的磁盘数据簇。

**文件偏移（File Offset）**从文件或指定数据流的第 0 字节开始；**簇号、块号和 LCN**属于文件系统分配坐标。只有结合映射表，才能将前者转换为后者。

<a id="section-2"></a>
## 2. 最小前置参数

任何文件位置换算至少应查明：

| 参数 | 主要来源 | 用途 |
|---|---|---|
| 文件系统类型及版本特征 | 引导扇区、超级块、工具解析 | 决定映射规则 |
| 文件系统相对起点 | 卷 / 分区布局 | 转换成设备字节偏移 |
| 逻辑扇区大小 | 设备或卷参数 | 将扇区号转为字节 |
| 每簇扇区数 / 每块字节数 | BPB、超级块等 | 计算数据单元大小 |
| 文件元数据标识 | 目录项、MFT 记录号、inode | 找到目标对象 |
| 文件大小及已分配范围 | 元数据及数据映射 | 判断有效数据和空间边界 |
| 块 / 簇映射 | FAT 链、Runlist、Extent、间接块 | 解析碎片化与空洞 |

只有已证实为线性平移的映射层，才能逐层相加起点。RAID 条带、LVM 分段和虚拟磁盘分配表等必须先解析实际映射，不能一律相加。不能预设文件系统起点就是整盘起点。

<a id="section-3"></a>
## 3. FAT12、FAT16、FAT32

FAT 文件系统以簇为主要空间分配单位。文件目录项记录起始簇、文件大小及属性等信息；后续簇通常通过 FAT 表项串联。

### 3.1 保留区、FAT 区和数据区

常见 FAT 布局为：

```text
文件系统起点
├── Reserved Sectors（包含引导扇区及保留结构）
├── FAT #1
├── FAT #2 ...（视 FAT 数量而定）
├── FAT12/16 固定根目录区（FAT32 通常不采用此结构）
└── 数据区（文件簇与目录簇）
```

设文件系统中的字段为：

- `RsvdSecCnt`：保留扇区数。
- `NumFATs`：FAT 表数量。
- `FATSz`：每张 FAT 表的扇区数（按文件系统版本选择正确字段）。
- `RootDirSectors`：FAT12/16 固定根目录占用扇区数；FAT32 通常为 0。
- `SecPerClus`：每簇扇区数。

则：

```text
FirstDataSector = RsvdSecCnt + NumFATs × FATSz + RootDirSectors
FirstSectorOfCluster(N) = FirstDataSector + (N - 2) × SecPerClus
```

这里结果是**文件系统相对扇区号**。有效的数据簇号通常从 2 开始，簇 0 和 1 不是普通数据区中的第一个、第二个簇。FAT12/16 的固定根目录结构也不能误作一般簇链。

`RootDirSectors` 常按以下关系求出（`RootEntCnt` 为根目录项容量，`BytsPerSec` 为每扇区字节数）：

```text
RootDirSectors = ceil(RootEntCnt × 32 / BytsPerSec)
```

### 3.2 FAT 链和碎片化

文件起始簇并不能单独确定完整文件的位置。读取当前簇的 FAT 表项，按链寻找下一簇，直到结束标记或异常。连续簇可以合并为区间；不连续簇必须分段处理。

FAT12 表项为 12 位并涉及跨字节取值；FAT16、FAT32 的表项宽度及高位保留约定不同。解析 FAT32 时不能将全部 32 位机械地视为有效簇编号。还需判断文件大小、坏簇标记、保留值及不同 FAT 副本是否一致。

### 3.3 删除与恢复的局限

删除目录项后的起始簇可能仍存在，但 FAT 链可能已清除或被重用。仅根据起始簇加文件长度进行连续读取，属于一种需要验证的恢复假设，并非原始簇链的证明。不能只凭文件头签名和起始簇断定全部数据连续、完整或未被覆盖。

<a id="section-4"></a>
## 4. exFAT：分配位图、FAT 与连续流

exFAT 与 FAT32 不能按相同规则机械解析。它使用 Allocation Bitmap 描述簇分配状态，并通过文件目录项集合（File Directory Entry、Stream Extension、File Name Entries 等）描述文件。File Name Entries 储存名称片段；Stream Extension 提供数据长度、首簇等关键字段。

重要概念：

| 字段 / 结构 | 含义 |
|---|---|
| `ClusterHeapOffset` | 簇堆起点（文件系统相对扇区） |
| `SectorsPerClusterShift` | 每簇扇区数为 `2^shift` |
| `FirstCluster` | 数据流的首簇号 |
| `DataLength` | 数据流长度 |
| `ValidDataLength` | 其中具有有效已初始化内容的长度 |
| `NoFatChain` | 某些流使用连续簇区间，无需沿 FAT 链寻址 |
| Allocation Bitmap | 记录簇是否已分配，不能独立替代文件关联元数据 |

对处于簇堆的数据簇：

```text
ClusterFirstSector(N) = ClusterHeapOffset + (N - 2) × SectorsPerCluster
```

结果仍是文件系统相对扇区。对于标记 `NoFatChain` 的连续数据流，可以按首簇、`DataLength` 和簇大小求出所需的连续簇范围，并与 Allocation Bitmap 及卷边界交叉核验；对通过 FAT 链描述的流则必须逐簇追踪。`ValidDataLength` 与 `DataLength` 需要分别理解，不能将未初始化区间误认成曾经实际写入的内容。

exFAT 的卷引导区字段以规定的移位方式编码扇区/簇大小；解析时应确认卷边界和字段有效性，而不是把某个 shift 值直接当作字节数。

<a id="section-5"></a>
## 5. NTFS：MFT、VCN、LCN 与 Data Runs

NTFS 通过 Master File Table（MFT）中的文件记录及其属性管理文件。MFT 记录号是文件系统对象标识，**不是簇号，也不是 MFT 记录在整盘中的字节偏移**。

### 5.1 驻留数据与非驻留数据

- **Resident（驻留）属性**：数据直接位于 MFT 文件记录的属性内容中。此时文件的数据开头可能根本没有独立分配的数据簇。
- **Non-resident（非驻留）属性**：数据通过运行区（Data Runs / Runlist）映射到文件系统中的逻辑簇。

因此，“所有文件都从某个起始 LCN 开始”是错误前提；小文件和部分元数据属性可以驻留。

### 5.2 VCN 与 LCN

| 编号 | 所属空间 | 含义 |
|---|---|---|
| VCN | 文件属性的数据流 | 从流起点顺序编号的虚拟簇 |
| LCN | NTFS 卷 | 文件系统中逻辑簇编号 |
| MFT Record Number | MFT 文件记录表 | 元数据记录标识 |

对于一个非驻留数据流，其逻辑偏移 `x` 所在 VCN 通常为 `floor(x / cluster_size)`；再由 Runlist 找到对应 LCN。如果目标逻辑区间落在稀疏运行区，则不存在对应的已分配 LCN。

### 5.3 Data Run 的语义

Runlist 描述连续 VCN 范围与对应 LCN 范围之间的映射。运行区描述中的位置增量通常相对于上一非稀疏运行区的 LCN，且带符号；错误处理符号扩展或把增量当成绝对 LCN，都会造成错误定位。

若某个运行区从 `VCN_a` 映射到 `LCN_b`，且目标簇在该运行区内，则：

```text
目标 LCN = LCN_b + (目标 VCN - VCN_a)
NTFS 相对字节偏移 = 目标 LCN × ClusterSize + 簇内字节偏移
```

该公式适用于普通未压缩、实际分配的运行区。压缩属性、稀疏属性、加密数据流以及特殊重解析对象要先处理其格式和映射语义。

### 5.4 多数据流、硬链接与元数据文件

NTFS 允许命名数据流（ADS）；一个文件名所关联的数据并不一定只有默认 `$DATA` 流。硬链接可使多个目录项指向同一文件记录。`$MFT`、`$Bitmap`、`$LogFile`、`$UsnJrnl` 等元数据文件本身也有位置映射与取证意义。访问控制、时间戳和日志记录不能仅通过文件数据簇得出。

<a id="section-6"></a>
## 6. ext2/ext3/ext4：inode、块与 Extent

ext 系文件系统主要使用 inode 记录对象元数据。inode 编号标识元数据对象，不是数据块号，也不能把 inode 号直接乘以块大小来获得文件位置。

### 6.1 块大小与超级块

超级块提供块大小、块总数、组参数及特性标志等信息。ext4 常见块大小为 1 KiB、2 KiB 或 4 KiB，但应以实际超级块和有效元数据为准。文件系统块号相对于文件系统起点，而不是自动相对于整盘起点。

### 6.2 Extent 与旧式块指针

ext4 通常以 Extent Tree 描述文件逻辑块范围和物理文件系统块范围。Extent 的逻辑起点、物理起点、长度以及未初始化状态共同决定映射；树可能有多层，不能只读取 inode 中一个浅层节点后就认定文件数据完整。

在某些 ext2/ext3 或兼容布局中，还可能使用直接块、一级/二级/三级间接块指针。取证程序必须先识别 inode 特性与文件系统版本，选择正确的映射方式。

### 6.3 Extent 地址计算

对于已初始化的普通映射区间：

```text
文件系统相对字节偏移 = 物理文件系统块号 × BlockSize + 块内偏移
```

其前提是文件偏移已经通过 extent 或指针映射到正确的文件系统块号。不能只用 `file_offset / BlockSize` 推断物理块号；碎片文件的逻辑块序号与实际文件系统块号可能完全不同。

### 6.4 内联内容和未初始化区间

ext4 可使用 inline data 等机制，使小内容存放于 inode 相关区域；也可存在未初始化 extent 和文件空洞。此类数据不能按普通已分配块直接定位。日志和元数据校验可以帮助交叉验证，但日志中是否保留具体内容取决于文件系统状态、挂载策略与历史操作。

<a id="section-7"></a>
## 7. 文件逻辑偏移不等于磁盘偏移

### 7.1 碎片化

文件的逻辑字节序列连续，但对应的簇或块可能分布在不同位置。用 `起始簇 + 文件偏移 ÷ 簇大小` 直接计算，只对已确认连续的映射区间有效。

### 7.2 稀疏文件

稀疏文件某些逻辑区间可能读取为零，但不占用实际分配块。此时不能为每个文件逻辑字节强行给出某个设备扇区。

### 7.3 压缩、加密、去重

文件系统压缩会使逻辑内容与存储的压缩字节不形成简单一对一对应；加密卷和文件级加密增加了解码层；去重、克隆和写时复制可能允许不同逻辑对象共享同一数据区间。取证记录应区分**逻辑解码内容**与**原始存储字节**。

### 7.4 符号链接、重解析点与硬链接

符号链接和重解析点可能指向其他对象或文件系统，路径解析可能跨越卷或目录树。硬链接可以让多个路径关联同一文件对象。文件名与路径不是可靠的独立数据位置标识。

### 7.5 内联或驻留小文件

NTFS 的驻留属性、ext4 的内联数据等使文件数据保存在元数据结构中。对此类文件，“第一个数据簇”可能不适用；应报告文件内容实际依附的记录或元数据位置，避免虚构簇号。

<a id="section-8"></a>
## 8. 已分配空间、未分配空间和 Slack

- **已分配空间**：文件系统目前分配给文件或元数据的存储单元。
- **未分配空间**：文件系统当前未分配的单元；可能残留历史内容，也可能已被清零或重用。
- **文件 Slack**：文件逻辑结束位置之后、其已分配单元末尾之前的空间；需要结合文件系统、分配粒度和实际取证视图区分不同类别。
- **未使用 / 未初始化范围**：不等同于曾经删除的数据。读出零值可能来自稀疏映射或初始化语义。

SSD、U 盘和 SD 卡可能存在 TRIM、垃圾回收与闪存重映射。一个未分配的逻辑 LBA 不保证仍能读取历史写入的旧字节，无法读取残留也不能倒推“从未存在过该文件”。

<a id="section-9"></a>
## 9. 删除文件的定位原则

被删除文件的目录项、元数据记录和数据块可能以不同速度被复用。即使能恢复文件名和文件大小，也不表示完整的逻辑到物理映射仍存在。

恢复判断需要分别说明：

1. 文件对象是否有可信的元数据标识。
2. 起始数据位置是原始元数据、日志、残留结构还是文件雕刻推断所得。
3. 是否还能获得完整簇链、Runlist 或 Extent。
4. 未分配范围是否已经被重写或复用。
5. 数据内容是否经文件格式结构校验，是否存在缺口或混入其他对象的字节。

文件签名扫描（file carving）可以找到候选数据，但签名出现的位置不必然是文件开头；完整恢复还需要尺寸、容器结构、内在一致性和相关元数据支持。

<a id="section-10"></a>
## 10. 取证工具中的定位字段

| 工具字段 | 可能的含义 | 应查证的问题 |
|---|---|---|
| `First Sector` | 首个扇区编号 | 设备绝对还是文件系统相对？从 0 起吗？ |
| `Physical Sector` | 软件所称实体位置 | 实际是设备 LBA 还是介质内部位置？ |
| `Cluster` | 文件系统簇号 | 簇号是否从 2 开始？ |
| `Block` | 文件系统块号 | 块大小和坐标原点是什么？ |
| `LCN` | NTFS 卷相对逻辑簇号 | 是否来自已解析 Runlist？ |
| `VCN` | NTFS 数据流逻辑簇号 | 是否已映射到 LCN？ |
| `File Offset` | 文件或流相对字节偏移 | 是逻辑解码后的文件还是原始块内容？ |
| `FS Offset` | 文件系统有关的偏移 | 指起始位置还是内部相对位置？ |
| `Image Offset` | 镜像数据流/容器有关偏移 | 该视图来自哪层数据？ |

对每个结果，保留原始工具字段名称及工具版本。需要跨软件比较时，统一换算为**同一逻辑设备数据流中的字节区间**，再考虑解析差异。

<a id="section-11"></a>
## 11. The Sleuth Kit 只读分析

以下为常用入口，参数应根据镜像布局和实际版本核实：

```bash
# 查看分区布局
mmls -b SECTOR_BYTES evidence.raw

# 从已核实的文件系统起始 LBA 读取文件系统信息
fsstat -b SECTOR_BYTES -o START_LBA evidence.raw

# 枚举文件系统目录，-r 递归；不要将输出中每个元数据地址当作扇区
fls -r -b SECTOR_BYTES -o START_LBA evidence.raw

# 查看特定文件系统元数据对象及其分配区间
istat -b SECTOR_BYTES -o START_LBA evidence.raw META_ADDRESS

# 根据文件系统元数据对象提取逻辑文件内容
icat -b SECTOR_BYTES -o START_LBA evidence.raw META_ADDRESS > extracted.bin
```

`SECTOR_BYTES` 和 `START_LBA` 均为占位符，前者是镜像所表示设备的逻辑扇区字节数，后者是同一粒度下的文件系统起始扇区号。`START_LBA` 是占位符，不是可直接复制执行的实际数字。`-o` 通常以镜像逻辑扇区为单位表示文件系统起点偏移。`istat` 中的对象地址语义依文件系统而异，通常不是“文件数据的绝对 LBA”。`icat` 生成的文件是逻辑内容，不保留其碎片原位布局；导出结果应单独保存哈希及操作记录。

对于 E01、AFF4 或虚拟磁盘镜像，先通过可靠的只读解析层获得正确逻辑数据流。不要把压缩证据容器本身的文件字节偏移与客户机虚拟磁盘扇区混用。

<a id="section-12"></a>
## 12. 文件定位的交叉核验流程

### 12.1 确定分析对象

记录证据哈希、镜像格式、证据编号、磁盘/卷层级、工具版本。确认读取的是完整设备逻辑流还是分区/卷导出流。

### 12.2 查明文件系统参数

核验文件系统起点、扇区大小、簇或块大小、元数据对象标识。必要时比较分区表、文件系统引导字段和工具自动识别结果。

### 12.3 从元数据重建映射

按照文件系统特性读取 FAT 链、exFAT 连续流标志、NTFS Runlist 或 ext Extent。将映射表示为有序的文件逻辑区间以及对应的存储区间；不能只保存一个起始扇区。

### 12.4 读取与对照

对普通已分配范围，从映射位置读取对应长度的数据，并与文件系统解析器提取的逻辑内容交叉比对。对压缩、稀疏、加密、驻留、内联等对象应使用相应语义，不强制逐字节对应磁盘原始字节。

### 12.5 报告不确定性

列明无法定位的区间、已损坏的元数据、可能的覆盖、多个冲突解释及验证局限。若仅依据文件头推断，应标明“推定位置”，不能写成“已确认的文件第一扇区”。

<a id="section-13"></a>
## 13. 适用于自动化取证的结构化结果

自动化工具应输出足以复核的映射，而非只有一个 `offset` 数字。以下是字段设计规范；其中的 `null` 表示无有效值或尚未确认，并非数值 0。

```json
{
  "evidence_id": "<evidence-id>",
  "source_stream": "<device-logical-stream-id>",
  "filesystem": "<FAT32|exFAT|NTFS|ext4|...>",
  "filesystem_origin_byte": null,
  "logical_sector_size_bytes": null,
  "allocation_unit_size_bytes": null,
  "file_object_id": "<filesystem-specific-object-id>",
  "data_stream": "<stream-name-or-default>",
  "file_logical_ranges": [],
  "storage_ranges": [],
  "unmapped_ranges": [],
  "mapping_method": "<fat-chain|runlist|extent|resident|carving|...>",
  "evidence_basis": [],
  "verification_state": "unverified",
  "limitations": []
}
```

对 `storage_ranges`，每段至少记录逻辑起点、长度、对应卷/设备相对起点、映射是否确定和是否为数据/元数据位置。采用非连续映射时，不得合并成一个虚假的连续区间。取证 Agent 应优先执行只读解析和交叉核验，不确定时保留未知值。

<a id="section-14"></a>
## 14. 报告用语与常见误判

| 不准确表述 | 更准确的表述 |
|---|---|
| 文件的 inode 号就是磁盘扇区号 | inode 是元数据标识，文件数据位置须解析块指针或 Extent |
| MFT 编号 × 簇大小就是文件地址 | MFT 编号标识文件记录，数据位置依属性的驻留或 Runlist 而定 |
| 文件偏移等于磁盘绝对偏移 | 文件偏移是逻辑坐标，需经过文件系统及卷映射 |
| 所有文件都有第一个数据簇 | 驻留、内联、稀疏及特殊对象可能没有独立首个数据簇 |
| 文件头存在意味着文件完整 | 文件头只提供格式线索，无法单独证明完整性 |
| 删除文件一定能读取原簇 | 元数据可能被清除，存储空间可能复用、TRIM 或清零 |
| 一个分区对应一个固定物理扇区空间 | 动态卷、RAID、虚拟磁盘可引入非平凡映射 |

正式结论宜采用：“在指定文件系统中，通过某种元数据映射，将目标数据流的逻辑范围映射到卷相对某数据区间；结合卷/设备起点，得到设备逻辑字节流中的相应位置。经指定工具与内容验证，映射可信程度为……”

<a id="section-15"></a>
## 15. 技术审查清单

- [ ] 文件路径、元数据对象和数据流已分别识别。
- [ ] 文件系统起点、簇/块大小及设备逻辑扇区大小已确认。
- [ ] FAT 链、exFAT 分配方式、NTFS Runlist 或 ext Extent 已正确解析。
- [ ] 非连续区间均单独记录，没有把逻辑连续误作物理连续。
- [ ] 驻留/内联、稀疏、压缩、加密等特殊映射已处理。
- [ ] 设备/卷/文件系统的坐标原点和单位均有注明。
- [ ] 文件逻辑内容与原始存储位置的关系经过独立验证。
- [ ] 删除或损坏对象的推断与确定事实已严格区分。
- [ ] 工具版本、证据哈希、原始输出及操作记录可供复核。

<a id="section-16"></a>
## 16. 可复算示例：碎片文件的第二段

以下为普通、未压缩、实际分配区间的教学算例，文件系统起点假设等于分区起点。

**FAT 示例。** 逻辑扇区 512 B，每簇 8 扇区，分区从设备 LBA 2048 开始；`RsvdSecCnt=32`、`NumFATs=2`、`FATSz=100`、`RootDirSectors=0`，则数据区从文件系统相对扇区 232 开始。文件簇链为 `2 → 5 → EOC`。文件偏移 4219 B 位于第二个簇、簇内 123 B，所以读取的是簇 5，对应设备字节偏移 `(2048 + 232 + (5-2)×8)×512 + 123 = 1179771`。若错误地当作连续簇 3，将读到其他位置。

**NTFS 示例。** 保持分区起点和设备扇区大小，簇大小设为 4096 B：VCN `[0,2)` 映射到 LCN `[100,102)`，VCN `[2,3)` 映射到 LCN `[300,301)`。文件偏移 8315 B 是 VCN 2、簇内 123 B，设备字节偏移为 `2048×512 + 300×4096 + 123 = 2277499`。LCN 300 属于第二段，不能用首段 LCN 100 加 VCN 2 替代。

两例都应由解析器导出的相应文件逻辑区间，与映射位置读取的字节交叉比较；这里验证了算术关系，没有声称用真实镜像完成恢复实验。
